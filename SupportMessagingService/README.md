Want to use `MessagingService` across multiple servers?

## Background

To test that `MessageService` works properly, I prepared an instance of Freedom Distribution v463.

### What URL Should We Expect?

In February 2021, Rōblox user @RakNetProtocol built ["a Node.js wrapper for interacting with the Roblox Message Router API"](https://devforum.roblox.com/t/messagingservice-in-nodejs-but-only-for-roblox-studio/1066274).

He designed his tool to [take advantage](https://devforum.roblox.com/t/messagingservice-in-nodejs-but-only-for-roblox-studio/1066274/4) of the API endpoint `https://messagerouter.api.roblox.com/v1/router/signalr`:

> it uses messagerouter.api.roblox.com/v1/router/signalr, it uses the same methods as the actual MessagingService, it uses the SignalR hub MessageRouterHub

### First Steps

That instance should contains a server-side script which does something like the following:

```lua
local MessagingService = game:GetService("MessagingService")
MessagingService:SubscribeAsync("Test", function(Message)
	print(Message.Data)
end)
```

Upon launching the server, I am greeted with this error message:

```
[FFlog::Error] Error: MessagingService error: This API is not enabled yet.
```

---

The next thing I should do is to find the appropriate FFlag to toggle the `MessagingService`.

Using [my FFlag-extractor tool](https://github.com/Windows81/Roblox-x64dbg-FFlag-Extractor/blob/main/test/v463-server.json#L5094C3-L5094C32), I found the best candidate to be `"DFFlagEnableMessagingService"`, which is set to `false` by default.

Nop. After enabling, I now get a different server-log error:

```
[FFlog::Error] Error: MessagingService: Service disconnected.
```

This is a misnomer. No connection to `https://localhost:2005/v1/router/signalr` was _ever_ made in the first place.

### Intercepting URL Construction

Something to note is that `messagerouter.api.roblox.com` refers to a subdomain.

According to my prior expertise, I should not rule out that `RCCService.exe` _wrongly_ constructs `messagerouter.api.{BaseUrl}` as the hostname, when we want the hostname to be `{BaseUrl}`.

Therefore, I should want to alter the behaviour such that no `"messagerouter.api."` section is prepended. We're using x32dbg to patch v463 `RCCService.exe` and achieve this result.

In x32dbg, searching for user-module strings yields one result for `"messagerouter.api"`:

```
0110A011 | 68 E8B8A201              | push rccservice.1A2B8E8    | 1A2B8E8:"messagerouter.api"
```

---

I added a breakpoint at the aforementioned executable address [`0110A011`], then traced to the `ret` statement [`0110A1CA`]. Upon executing `utf8([eax])` in the x32dbg command bar, I retrieved an _almost_ desired:

```
"https://messagerouter.apilocalhost:2005/v1/router"
```

---

There are multiple ways to replace `"messagerouter.api"` with an empty string. For this patch, I'm choosing to zero the entire string region beginning at `01A2B8E8`:

```patch
-01A2B8E8  6D 65 73 73 61 67 65 72 6F 75 74 65 72 2E 61 70  messagerouter.ap
+01A2B8E8  00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00  ................
-01A2B8F8  69 00 00 00 75 6E 69 76 65 72 73 65 49 64 3D 25  i...universeId=%
+01A2B8F8  00 00 00 00 75 6E 69 76 65 72 73 65 49 64 3D 25  ....universeId=%
```

Now, retracing execution to `ret`, we get:

```
"https://localhost:2005/v1/router"
```

---

However, the same symptoms persist:

```
[FFlog::Error] Error: MessagingService: Service disconnected.
```

As before, no connection to `/v1/router/signalr` is made in the first place.

### Enabling Deeper Error Trace

Further stepping through from the aforementioned breakpoint at `0110A011`, I discovered that some execution flow depends on the value of a fast-_log_ variable `DFLogSignalRConnection`:

```
01367812 | A0 9465FB01              | mov al,byte ptr ds:[<DFLog::SignalRConnection>]
```

The annotation was generated by [my FFlag-extractor tool](https://github.com/Windows81/Roblox-x64dbg-FFlag-Extractor/tree/main).

---

Upon setting `DFlogSignalRConnection` to a high number, additional useful messages became visible:

```
[DFLog::SignalRConnection] SSignalR connection started exception: WinHttpSendRequest: 12175: A security error occurred
```

When `WinHttp` returns with an error code 12175, this is likely due to the HTTPS connection being unsigned.

_Note that `WinHttp` operates completely separately from `libcurl` and gets used in a very small minority of HTTP traffic._

### Adding Call to `WinHttpSetOption`

I derived relevant [a code sample](https://github.com/nival/Prime-World/blob/c59acd7ecedfcb7392f45452a7312199e697b949/pw/branches/r1117/Src/Client/BrowserPlugins/FireFox35/HTTPDownloader.cpp#L209) which uses:

```cpp
#include <windows.h>
#include <winhttp.h>

// EXISTING CODE; ignore arguments `...` and retrieve resultant `hRequest` in `eax` register.
HINTERNET hRequest = WinHttpOpenRequest(...);

// NEW CODE; we will assemble *everything here and below* in x86 manually.
int options = ( // 0x3000
	SECURITY_FLAG_IGNORE_CERT_CN_INVALID |
	SECURITY_FLAG_IGNORE_CERT_DATE_INVALID |
	SECURITY_FLAG_IGNORE_UNKNOWN_CA |
	SECURITY_FLAG_IGNORE_CERT_WRONG_USAGE);

WinHttpSetOption(
	hRequest,                      // eax
	WINHTTP_OPTION_SECURITY_FLAGS, // 0x1F
	&options,                      // 0x3000
	sizeof(options)                // 0x4
);
```
